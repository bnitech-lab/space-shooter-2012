# Space Shooter (2012)

A Galaga-style shooter for Windows, written in C++ against the plain Win32 API with GDI drawing (no MFC). The window has an 800 x 550 play field over a scrolling star background and a side panel with the stage, score, play time, weapons and lives. A formation of 30 one-eyed slimes (7 hits each) and 20 saucers (15 hits each) sweeps left and right across the top, and each enemy changes its picture as it takes damage. After a few minutes, slimes start leaving the formation two at a time and home in on the players. A boss circles the edge of the field. Every hit scores 10 points, and touching any enemy ends the game.

The player has two weapons: twin straight shots (unlimited) and bouncing shots that ricochet off the edges of the field (20 per supply). A "B" item floats around the field now and then, and picking it up refills the bouncing shots. Each frame is drawn into an off-screen bitmap first and then copied to the window (double buffering), so the screen does not flicker. One or two players can play on the same keyboard.

| | Player 1 | Player 2 |
|---|---|---|
| Move | arrow keys | T up, F left, G down, H right |
| Fire (one-player game) | Space | |
| Fire (two-player game) | Shift | Ctrl |
| Weapons (one-player game) | 1 straight, 2 bouncing | |
| Weapons (two-player game) | P straight, [ bouncing | Q straight, W bouncing |

On the start screen, press 1 or 2 to choose the number of players. After GAME OVER, press Enter to go back to the start screen.

## Background

- Year: 2012.
- Made alone by Dawn at university; it grew out of an assignment for a Visual C++ course.
- The project skeleton (`WinMain`, the About box, `StdAfx.*`, the resource script) was generated by the Visual C++ AppWizard, which is why the project and window are still called `VC0608`.

## Build (Windows)

The project targets Win32 (x86) and only builds on Windows.

- Visual Studio 2013 or newer, with the C++ desktop workload: open `VC0608.sln`. Newer versions offer to retarget the project to the installed toolset and Windows SDK; accept, choose Debug or Release for Win32, and build. The program needs no files at run time, because all pictures are compiled into the executable as resources.
- Visual C++ 6.0: `VC0608.dsw` and `VC0608.dsp` are the original project files. Visual C++ 6.0 cannot read UTF-8 source, so convert `VC0608.cpp` back to code page 949 first (for example `iconv -f UTF-8 -t CP949`, after removing the byte-order mark).

This release was not built on Windows (none was available); see "Changes" for what was checked.

The side panel asks for the Korean font Gulim and prints an infinity sign. Both come out as intended on Windows with a Korean system locale; on other locales Windows picks a fallback font and the compiler may turn the infinity sign into `?`.

## Changes for this public release

- `VC0608.cpp` was converted from the Korean CP949 encoding to UTF-8 with a byte-order mark, which Visual Studio reads without extra options. Converting it back gives the original bytes exactly. The other text files were already ASCII (including `VC0608.rc`) or UTF-8 and are unchanged.
- Build and IDE leftovers were not copied: `.sdf`, `.APS`, `.ncb`, `.opt`, `.suo`, `.plg` and `UpgradeLog.htm`. The AppWizard `ReadMe.txt` was also left out; the project files still list it, which Visual Studio shows as a missing file but does not affect the build.
- The original start screen, player ship, enemies with their damage frames and the boss were copied from a commercial arcade game, so they were replaced with new drawings for copyright reasons. The two shot pictures were replaced too (the straight shot looked like the same game's missile, and the origin of the bouncing shot was unknown), and so were the two icons (a barcode picture of unknown origin). The new pictures keep each file's name, pixel size and 8-bit BMP format (4-bit for the icons), so `VC0608.rc` compiles them unchanged. They are drawn in code by [`tools/DrawArt.java`](tools/DrawArt.java) and can be regenerated with JDK 11 or newer:

  ```sh
  java tools/DrawArt.java
  ```

- Kept as they were, because they are the author's own drawings: the star background (`bitmap1.bmp`), the "B" item (`bitmap_i.bmp`), the GAME OVER caption (`bitmap_o.bmp`) and the black side-panel bitmap (`bitmap_m.bmp`, loaded but not drawn by the code).
- Four more bitmaps in the old folder were not used by the resource script and were left out.
